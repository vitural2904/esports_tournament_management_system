# Domain docs

## Before exploring code

Read root GLOSSARY.md if present.
Read relevant decisions in docs/adr/ if present.
If absent, proceed silently.
Domain-modeling creates these docs when terms or decisions are resolved.

## Layout

One domain context:
- GLOSSARY.md at the repo root.
- ADRs under docs/adr/.

## Vocabulary

Use the glossary's terms in issues, proposals, hypotheses, tests.
Reconsider unknown terms. Record real gaps for domain-modeling.

## Decisions

Flag conflicts with existing ADRs.
Name the ADR. Explain why the decision should be reopened.
